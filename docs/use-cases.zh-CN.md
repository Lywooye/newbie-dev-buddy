# 小白开发搭子的三个使用场景

[English](use-cases.md) · [项目介绍](../README.zh-CN.md) · [常见问题](faq.zh-CN.md)

这份文字版围绕同一个虚构书签小助手展开：记录标题、网址和标签，并导出 CSV。下述模块、方案修订、实施与程序检查可以通过[演示脚本](../examples/bookmark-demo/README.md)复现；对话与决定是预设情境，不是真实用户反馈或模型会话。

## 从想法开始规划模块

**适合的问题：**“我想做一个小工具，但不知道先做什么、代码怎样分工。”

先让助手说明第一版范围，再提出模块职责和关系。书签样例把第一版限定为本地 CSV 导出，采用三个模块：

| 模块 | 负责什么 | 不负责什么 |
|---|---|---|
| 书签数据 `M-STORE` | 读取标题、网址和标签 | 不筛选、不生成 CSV，导出不得改原始数据 |
| 表格导出 `M-EXPORT` | 接收书签列表并生成 CSV | 不保存书签 |
| 使用入口 `M-APP` | 接收选项，连接读取与导出 | 不覆盖用户文件 |

入口依赖数据和导出模块；导出模块接收列表，不需要负责从文件读书签。你可以审阅：“每部分的职责能说明白吗？第一版有没有不必要的功能？原始数据会不会被改？”确认后由助手用 `init` 保存结构。

**实际证据：**演示中的地图由脚本预先准备，CLI 真实保存它；这一步不验证 AI 自动设计架构的质量。搭子本身不生成设计，三个模块也不是所有项目的固定模板。

在助手中可以说：

```text
使用 newbie-dev-buddy。我要做一个本地书签导出工具。
先讨论第一版需要哪些功能，用日常语言说明各模块的职责和关系。
列出不确定的地方，给我审阅后再保存地图。
```

## 一起审阅和修改方案

**适合的问题：**“AI 的第一稿和我想的不一样，改方案后又怕丢掉以前的决定。”

| 修订 | 候选方案与决定 | 实际记录 |
|---|---|---|
| `C-EXPORT` r1 | 全量导出；预设决定为拒绝，要求按标签导出并保留默认行为 | 第一稿 Markdown、拒绝决定和理由 |
| `C-EXPORT` r2 | 增加可选 `tag` 和入口 `--tag`；预设决定为接受 | 第二稿、具体版本的接受记录及实施事件；r1 保留 |

第二稿只改导出模块和入口，数据读取模块保持不变。完成条件是可观察的行为：传 `--tag learning` 得到两条书签；不传标签得到三条；不存在的标签只得到 CSV 表头；原始数据不变。

**实际证据：**脚本通过真实 CLI 拒绝 r1、接受 r2，记录开始与完成，实际修改程序并检查上述行为，同时比较第一稿文件指纹确认它未被覆盖。检查成功是这个样例的程序结果；Kit 未接入，验收状态仍为 `not_run`。

可以让助手把候选与这些审阅问题一起展示：“这次改动影响哪些模块？哪些行为应该保留？怎么观察是否完成？还有什么没核实？”如果要用模块验收，再按[验收规则](../references/verification.md)准备可信 Kit、配置和测试，确认检查计划后实际运行；这个演示没有完成该步骤。

## 换一个对话继续开发

**适合的问题：**“前一个对话太长了，新的助手怎么知道做到哪一步？”

新会话先读当前状态、模块地图、已接受的 `C-EXPORT` r2 和实施记录，再核对源码。它应该区分：第二稿已实施；第一稿曾被拒绝；样例行为已检查；Kit 尚未运行。

在已安装 Skill 的 Codex 中可以说：

```text
$newbie-dev-buddy
请先读这个项目的 MODULES.md、C-EXPORT-r2.md 和实施记录，再核对源码。
告诉我已完成什么、哪些没验收、下一步有哪些选择。先不要改代码。
```

其他助手用各自的[实际调用方式](../references/agent-support.md)。你不需要重新口述每一步，但仍要补充记录中没有的需求，并核对过期证据。

**实际证据：**演示最后启动新的 CLI 进程读取文件，返回 r2 已实施、无该记录检查出的源码漂移、Kit 未运行。这验证文件记录可被新进程读取，不等于已经验证新模型跨会话理解和交接；上面的提示词是试用方法。

## 自己核对输出

从仓库根目录运行，选择一个尚不存在的输出目录：

```sh
python3 examples/bookmark-demo/replay.py --output /tmp/newbie-dev-buddy-bookmark-demo
```

需要 macOS/Linux 或 WSL、Python 3.9+，无需模型、CodeGraph 或 Kit。脚本拒绝覆盖已有目录，不安装或上传任何文件。详细文件位置见[复现说明](../examples/bookmark-demo/README.md)。

打开生成的 `evidence.json`，核对 `checks` 中的 `selected_rows: 2`、`all_rows: 3`、`empty_rows: 0`、`source_data_unchanged: true`、`first_draft_unchanged: true`，以及 `kit_verification: "not_run"`、`real_model_session_tested: false`；再看项目内的原始 Markdown。文字版和视频都只是同一合成例子的说明，不是生产项目效果评估。
